# Changelog

All notable changes to this extension are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- **Icons.** The extension has its own icon: the Pathix path mark, a rising path whose edges run into a blue node, on a dark tile. The manifest names 16, 32, 48 and 128 px PNGs for the toolbar, the extensions page and the stores, rendered from `static/icons/icon.svg` by `npm run icons` with the Chromium the smoke test already uses. The release check's 128 px icon requirement is now met. The same script writes the Edge 300×300 logo and a first Chrome small promo tile into `store/assets/`.

- **The card from the keyboard and screen readers.** The popup has a **Card for the selected field** button that opens the card for the field that has focus, or says that no field is selected, or that the selected field has no card. A card opened from the popup, the command or an X-ray line moves focus to its title, is a dialog named by the column, and gives focus back on Escape or its close button, to the field's control when D365 replaced the one that had focus. The card updates in place as it loads, so a screen reader announces it once, and is marked busy until it has loaded. A card opened by hover never takes focus, and still closes when the pointer leaves it. The card now sits inside the page body, so screen readers reach it.
- **A toolbar popup.** Clicking the toolbar icon opens a small window with every form feature: the tab's connection (Lite, or the environment and its scan's age, or what is wrong, with **Open options** when the fix is there), an **X-ray** switch that shows its current state, and **Event map**, **What changed** and **Save preview** buttons that open their panels on the form. Each shows its keyboard shortcut. The form's state comes at once; the connection line says "Checking Pathix…" until Pathix answers, and never holds up the buttons. On a page with no record form the controls stay visible and turned off; when the tab does not answer, it also says to reload the page if a form is open, which covers a Dynamics page the extension was reloaded under. In Lite, X-ray and Save preview are turned off alike: "Uses your organization's Pathix". Turning the admin overlay on still works when the browser's permission prompt closes the popup. The popup also carries the admin center overlay switch, with the options page's logic, and links to the options and the demo. The manifest gains `action.default_popup` and a new toolbar title, and no permission.
- **X-ray lines sit on their own row under each field.** On a real form a side label has no data-id and a long id ending `-<control>-field-label`, which the line now finds by suffix; and the line was written into the label's no-wrap flex row, squeezing side labels to one character. It now goes after the label's nearest ancestor whose parent stacks its children, so the label keeps its width. Placement no longer looks for Level Up's chip, so the content script reads no D365 text at all. A pass that finds the line in place reads no computed style and writes nothing. The place is worked out again when the layout changes with the same nodes (a class or style change inside a field, a field container's size, a window resize), so switching between top and side labels never squeezes a label. Class changes above the fields, such as the focus classes Fluent UI toggles on the body on every click, are ignored and read no style. Each pass reads all the layout it needs before it writes a line, so turning X-ray on over hundreds of fields lays the page out once, and a field that grows or shows a message re-places that field alone. A visible field with no place for a line is counted, and the X-ray panel says "N visible fields could not be marked"; hidden fields are not counted. The bare `<label>` fallback skips labels inside the control itself.
- **Keyboard shortcuts are browser commands.** The shortcuts are now the manifest's `commands`, which the user can rebind or clear at `edge://extensions/shortcuts`, and the popup shows each one's current key with a **Change keyboard shortcuts** link. The extension sets one default, Alt+Shift+Q (Control+Shift+Q on a Mac), which opens the popup. X-ray, the event map, what changed, the save preview and the focused field's card each have a command with no default key: a shortcut works in every tab, so each is the user's choice. The page has no key handlers any more, so Edge's Alt+Shift+S (Visual Search) no longer hides the save preview. This replaces the modifier guard the review fixes added to those handlers: with no handler on the page, no typed character is taken there. A command's key opens its panel and no longer closes it; Escape does. `commands` is a manifest key, not a permission.

Its footer line says "Registered isn't the same as writes."

Each line is ✓ ruled out, ✗ the cause, or ? when Lite can see something but cannot read its logic. The lines: whether Dataverse allows updates to the column; column security and whether your own profiles grant update; the control set read-only in the form definition; active business rules that use the column (named); your own Write depth on the table; OnLoad and onChange form scripts that might lock it (named, never claimed); and the record itself, which Lite does not read. A read Lite is refused says "You don't have access to ..." and stays on the list. Footer: "Pathix maps everyone's access, not only yours."

Each says what to do next; "not set up" and "signed out" carry an **Open options** button. Before the first Completed scan, connected cards and X-ray say so instead of drawing an empty card.

It clears on tabs that are not connected, on sign-out and on a new Pathix address, and it is refreshed when the tab comes to the front and every 10 minutes while it is, so a form left open keeps a true age. The incomplete-list copy now says Lite could not read every page, which is what paging leaves behind. The contrast line's number is Pathix's `platformDependentCount`, so the connected card no longer calls `RetrieveDependentComponents`; a count Pathix did not measure reads "not in this scan", never zero. Each logic writer shows its triggers from the writers row, with the filtering columns, "Fires on every update" and a cloud flow's row-filter flag, and a plugin step lists its images. `/components/{id}` is read only for a listed plugin step, or for a row from an older Pathix. On a field the form shows read-only, the card opens with **Why can't I edit this field?**: the form line from Pathix's scan, matched to the hovered control by id (an unlisted control is unknown, never the form's fold), column security from Pathix's grants, and your own profiles and table access read live and tagged "live". - **Form event map (Lite).** Press Alt+Shift+E on a form to see every handler its definition registers: the event (OnLoad, OnSave, OnChange per column, a tab's events, a control's events), the library, the function and whether it is enabled. Platform-loaded handlers are tagged internal, not hidden. If the definition cannot be read, the map says so and never reads as "no handlers". It reuses the form definition query the checklist already makes, so the allowlist and the page bridge are unchanged. A hand-written stand-in fixture, `forms-account-events`, covers tab events, control events, OnChange per column and disabled handlers until the query of the same name is captured.
- **Form event map (connected).** With a Pathix address saved, Alt+Shift+E fills the same panel from Pathix's latest completed scan: `GET /environments/{id}/forms/{formId}/handlers`, keyed by the form id the page already reports, through the service worker and the shared response cache. No new page-side read, permission or dependency. It shows "As of" the scan's date. A form Pathix could not model (its definition was not read, or the scan holds no handler data) is unknown with the reason in words, a 404 says the form is not in Pathix's latest scan, and a failed request is unknown; none reads as "no handlers". The handlers are numbered only when the scan recorded their order; otherwise the panel says so and the rows are not a sequence. Disabled and platform-loaded handlers are tagged, and a handler whose enabled flag the form did not state is "enabled not stated". The API slice gains the new path and its three schemas. Built against a Pathix change that had not been released yet.
- **What changed.** Press Alt+Shift+C on a form for what changed on its table. In Lite it lists the table's plugin steps, classic workflows, business rules and forms by when each was last modified (a form by when it was last published: Dataverse keeps no `modifiedon` for forms), newest first. It says "modified" or "published", never what changed, and a source it could not read is named and never counted as nothing. The step and process reads are the registered card's own queries with `modifiedon` added to their `$select`, so the Lite allowlist gains no table. One new query reads the table's forms, and its fixture, `forms-modified-account`, is a real capture. Only the `modifiedon` values in the `plugin-steps-account` and `workflows-account` fixtures are still hand-written stand-ins, marked in each file.
- **What changed, connected.** The same panel shows Pathix's change ledger for the table (`GET /changes`, now in the API slice), grouped by scan. A row appears when the ledger ties it to the table (writes and reads of its columns, column changes, column security); a component that was only added, renamed or edited is not tied to a table, and the panel says so and links to the full ledger. A failed read is "could not read", never "no changes".
- **Changed since the last scan, live.** Where a component Pathix knows (the writers on the hover card, the components in the ledger) has a live `modifiedon` (a form's `publishedon`) newer than the latest Completed scan, a "changed since scan" badge says so, labelled "live" (the freshness case of the data boundary). The read is the content script's own, through the allowlisted Dataverse client, for plugin steps, workflows, business rules, flows, forms, views and charts. A component it cannot read is "could not be checked", never "unchanged". Nothing it learns goes to Pathix or into storage.
- **Power Platform admin center overlay (M14).** An opt-in overlay for `admin.powerplatform.microsoft.com`, connected-only. The options page has a **Show Pathix in the admin center** switch. Turning it on asks the browser for that one host and registers the page script at runtime; turning it off, or the browser removing the permission, unregisters it and removes what it drew. On a role's editor page, a banner under the breadcrumb reads "Assigned to N humans and M integrations", with the findings that name the role and the scan date. On the role list, each role carries a badge with its direct assignments and findings. On application users, each row whose Application ID Pathix knows carries a chip with its role count. The page script reads only ids from the address path and Application IDs from grid cells, makes no network call and never touches the page's tokens, storage or cookies; the service worker asks Pathix with the extension's own sign-in. Anything that does not match, or does not answer, leaves the page untouched, and a part that failed reads "unknown", never "0". `GET /roles`, `/roles/{id}`, `/findings` and `/principals` join the API slice. Maintainer approval, 2026-10-07: the admin host as an optional host permission, and the `scripting` permission for runtime registration. Review round 1: a badge or chip follows the id its row shows now, a role with business unit copies reads "N+ assigned", and the page-side fitness tests also cover the shared modules in the built `admin.js`. Review round 2: the role editor banner follows the same rule as the badge ("Assigned to at least ...", findings "At least N", a zero reads unknown), a findings count that leaves out business unit copies reads "N+" on the badge, the shared modules in `admin.js` are also held to the address, node-text, attribute and markup-from-string rules, and the smoke test covers a reused row whose new id needs a second request. Review round 3: with business unit copies a holder count of zero reads "? assigned" on the badge, in words in the tooltip, and a zero part is left out of "Assigned to at least ..."; the findings severity reads "highest seen"; a role whose only content would be the copies note draws no banner. Gaps listed in the PR: Pathix's role list has no parent-role id or human/integration split, its findings list has no triage status or role filter, and it has no one-row lookup by Application ID.

- **Save preview (connected).** Press Alt+Shift+S on a form for what is registered to fire when the record is saved, one hop, from Pathix's `GET /tables/{logicalName}/save-pipeline`. It reads top to bottom: the form's OnSave handlers, then one timeline with a group per stage present, in the platform's order (pre-validation, pre-operation, the save as the main operation, post-operation, with Microsoft's internal stages and the deprecated stage as tagged groups between), and the asynchronous lane marked unordered; entity business rules, and entries whose stage or mode is unknown, are listed apart. A group that holds only Microsoft entries is one line with its count. Order unknown, tied order, row filter set, row filter unknown and all-tables are written as text on the entry, the matched columns (or "any update") sit under it, the headline ends with "and N disabled", entries from Microsoft publishers fold, and every disclosure code Pathix sends is rendered as a sentence. A form whose handlers Pathix does not model reads as unknown, never as an empty list. A failed request is unknown, never "nothing fires". Lite says the preview needs Pathix.
- The page bridge carries two more things: whether a save would create or update (`saveKind`, a fixed word) and the names of columns the form submits on every save (`alwaysSubmitColumns`, from the column's submit mode). The page script is now held to a closed set of Xrm getters by `test/page-source.test.ts`. The request sends the table, Create or Update, the form's id and column names, and sends no columns at all on a create.
- The response cache keeps at most 500 answers, oldest dropped first, since a save preview has one key per set of edited columns. A failed Pathix answer now carries its HTTP status.

### Changed

- **The authorship note names Pathix's third exception**. In a newer Pathix, a harvested catalog of the components Microsoft creates unmanaged at provisioning also sets `isSystem`. It covers views, dashboards, duplicate-detection rules, a Copilot agent and attribute maps, and it only settles what the publisher left undecided. `DESIGN.md` and the comments in `api.ts` and `save-preview.ts` now say publisher identity plus three exceptions. No code changes: the card and the save preview fold on the flag, so these rows move to the Microsoft group on their own. A test pins that a provisioned attribute-map writer folds.
- **The connected event map names the form, and refuses another table's answer**. Pathix's handlers answer now carries the form's name and its table. The subtitle shows the form's name, as Lite does. An answer whose table is not the open form's is shown as unknown, never as the wrong form's handlers: a form id read from the field labels can be another form's. An older Pathix sends neither field, and its answer is taken as before. The contract slice is regenerated with the two fields.
- **What changed vouches for every scan in its window**. Connected, the panel reads `windowCoverage` from `/changes` and says on how many of the window's scans changes or findings were not compared, or not recorded. It no longer says "Pathix recorded no changes tied to this table" when some scans compared nothing, and with no scan in the window it says nothing was compared. An older Pathix falls back to the latest scan's finding gate. The contract slice is regenerated from Pathix main.
- **The connected card calls the platform count "dependency records"**. Pathix now labels `platformDependentCount` as the column's Dataverse dependency records. The contrast line reads "Dataverse has N dependency records. Pathix found M writers.", no longer "Dataverse tracks N dependencies", so it is not read as Lite's "tracks N components". The "?" says the count is usually the one in Dataverse's Show dependencies view but can differ, because that view groups some records differently. No contract change.
- The README says that Pathix behind a path prefix (an application proxy at `/pathix`, say) is not supported: the extension keeps only the address's origin.
- **The extension acts only on Dynamics 365 org pages.** The content scripts still match every `https://*.dynamics.com/*` page, but both now check the host first and run only on `<org>.crm.dynamics.com` or `<org>.crm<N>.dynamics.com`, any region. On Business Central, Finance and Operations, Commerce and other dynamics.com pages they set no flag, add no listener and send nothing, so nothing of the extension can be seen there. GCC (`crm9.dynamics.com`) is covered; GCC High, DoD and China are not supported yet, and the popup says so when a tab does not answer. No manifest change.
- **The manifest carries store copy.** The name is "Pathix for Dynamics 365", with no "(prototype)", and the description says what the extension does in Lite and with Pathix, and that it is not affiliated with Microsoft. The release check now refuses a manifest whose name or description says "prototype" or "not for distribution", or that has no 128 px icon in the package. No icon exists yet, so a release tag fails until one is added.
- **X-ray v2: one line under each label.** X-ray no longer draws shaded boxes over the form. It writes `W: 7  R: 8  F: 5  [flag] 0` under each field's label, after Level Up's logical-name chip when there is one. W and R count the writes to and reads of the column, forms left out, one per component as the hover card counts them; F counts the distinct forms that carry the column, found by the Form component type in both the writers and the dependents, so a form that only shows the column read-only is counted (F is unknown if either answer is missing); the flag is the open findings, read for the whole form in batches of fifty columns. A count that could not be loaded shows `?`, never 0. The line is the extension's own element with a closed shadow root, set with `textContent` only, and it never changes Dynamics 365's own elements. A MutationObserver puts it back when the form re-renders, including when a tab's fields first appear. It is a button: tab to it and press Enter to open the card. Turning X-ray off removes every line. X-ray stays connected-only; in Lite it says Pathix is not set up and writes nothing. It shares the hover card's response cache and its limit of four Pathix reads in flight.
- **One findings icon.** The flag is lucide's `Flag` (lucide-react 1.11.0, ISC), the icon the Pathix UI uses for findings, inlined in one module with no new dependency. It is used on the X-ray line and on the hover card. It inherits color and never encodes severity.
- **The card says "Findings", not "Signals".** The copy and the model and style names are renamed. The Open in Pathix link keeps `tab=signals` until the Pathix UI renames its tab.
- The old overlay's geometry code is gone.
- **Paging.** The Lite client follows `@odata.nextLink`, so a table with more steps, processes or dependencies than one page no longer undercounts. The link is a full URL from the server, so it is followed only on the page's own origin, for the same resource and with a query that still passes the allowlist, up to 20 pages. A link that is refused, fails or repeats leaves the answer marked incomplete: cards say "at least", and checks that need the whole list show ?.
- Footer lines now name what the card cannot see and what Pathix does about it, with the word **Pathix** as the link to pathix.app. Fires on change: "Registered isn't the same as writes. Pathix reads plugin code, scripts and flows to show what actually writes this column." Dependencies: "Dataverse can't see inside plugin code. Pathix reads it to find what writes this column." Why locked?: "This checks your own access only. Pathix maps who can edit this column across your organization." The **Lite** chip's tooltip says "Reads Dataverse metadata as you. Connect Pathix to see what actually writes each column."
- When nothing is registered, the Fires on change tab names what it read: "No plugin steps, classic workflows or business rules are registered to fire when this column changes." Lite never reads cloud flows.
- Microsoft publishers match Pathix's own classifier: `MicrosoftCorporation`, `microsoftdynamics`, `MicrosoftDynamics365`, `MicrosoftCorporationscm`, `microsoftcrm`, `dynamics365customerengagement`, `adxstudio`, `msdyn`, `PowerCat`, and any unique name starting with "Microsoft", ignoring case.
- Why locked? reads the table's Write privilege from its definition (`EntityDefinitions(...)?$select=Privileges`) instead of building `prvWrite<SchemaName>`, which does not exist for activity tables such as email.
- Releases are created as drafts, only from tags on `main`. A read-only job builds and checks the zip; a separate job with write access downloads it, checks it again and creates the draft. It installs nothing.
- The demo page says "Sample data", since some bundled fixtures are hand-written stand-ins.
- **The admin center overlay uses Pathix's role and principal additions.** A role's business unit copies are folded into the root role by `parentRootRoleId`, so the badge and the banner show the role's whole numbers with no "N+", "? assigned" or "at least". A scan that predates that column keeps those hedges where rows share a name. The banner's split comes from the role list, with platform-managed users (Power Pages site users, agents) counted apart, never as humans, and no request per role. The banner and badges say "open findings", read from `/findings/open-counts?roleId=`: Open or Reviewing in the admin's triage, without system noise and suppressed types. A role the answer leaves out is unknown. Application users are looked up with `/principals/by-app-id`, one read per visible page instead of paging every application user 200 at a time; a lookup with no scan behind it draws nothing. A role page is two reads, a role list one plus one per 100 role ids. `/principals/by-app-id` joins the API slice; `/roles/{id}`, `/findings` and `/principals` leave it.
- **The Pathix address is all the options page asks for.** The client-ID field is gone. Sign-in reads the extension's client ID and its read-only scope from Pathix's `/config` (`extension`) and asks Entra for `Pathix.Read` only, never the web app's `Pathix.Access`. An older Pathix with no `extension` key, a Pathix with no extension registration, a registration whose values fail the checks (including a client ID that is the web app's, or a scope that is not the web app's with `Pathix.Read` in place of `Pathix.Access`), and a Pathix with sign-in off each get a plain line on the options page, no Sign in button, no request to Entra and no stored token; cards say Pathix is not set up. A token whose `scp` grants anything beyond `Pathix.Read` is discarded before it is stored, and the options page asks the administrator to remove the other permissions and their consent. The refusal is remembered and kept in session storage, so even across a worker restart the worker asks Entra nothing more until the options page reads `/config` again, the address changes or five minutes pass from the refusal, and cards and the badge say "not set up" together. A "no sign-in" answer from `/config` is remembered for five minutes too. Concurrent requests share one sign-in and one `/config` read, and a failed sign-in never removes a token another saved after it began. A sign-in that finishes while `/config` is read again keeps its token; one whose settings changed meanwhile keeps nothing and says so. Stored tokens carry the Pathix address, authority, client ID and scope they were requested for, and a cached token is reused only when all four match. A `/config` that does not answer reads as "Could not reach Pathix just now", never as a failed sign-in, and a 200 that is not Pathix's settings is unknown. The sign-in settings are re-read after 5 minutes, and a connection status learned while sign-in became unavailable is never kept. A client ID stored by an earlier build is ignored, and removed on update, on the next save and with the address. The API slice gains `extension` and `ExtensionRuntimeConfig`. A new smoke file checks the options page against a fake Pathix.
- **No script ever runs on the Pathix origin** (maintainer decision, 2026-10-09). A count of business rules Lite cannot match reads "the N active business rules Lite can see" when the list may be partial. The team and role reads start alongside the depth read instead of after it.
- **A Write grant narrowed by a record filter no longer reads as every record.** Organization depth counted as ✓ "Your security roles grant Write on every account record" even when the role's privilege carried a record filter. Only an empty `RecordFilterId` or the empty GUID now counts as none; any other value says the grant covers "the account records a record filter selects", and an answer with no `RecordFilterId` is unknown. The read depths follow the same rule.
- **A sign-in no longer hangs on Entra, and a silent renewal never switches account.** Redeeming the sign-in code at Entra's token endpoint had no time limit; it is now aborted after 15 seconds and the user stays signed out with "Microsoft Entra did not answer in time." A background renewal whose token names a different account from the one the user signed in as is not kept, so the user is signed out until they select Sign in again, never quietly signed in as someone else.
- **A team role's Write no longer reads as every record when a record filter could narrow it.** A team's depth mask carries no record filter, so Why locked? said ✓ "A role you hold through a team grants Write on every account record" even on a privilege a role can filter. It now says so only when the table's definition says the Write privilege cannot take a record filter; otherwise the line is ? and says a record filter may narrow it. Business Unit and Parent: Child depths on security roles no longer count a team in the user's own business unit as reached, because nobody has verified whether that depth is anchored at the user's unit; one switch in the code names the live check that settles it. The team line names what may be missing (teams, roles, or both), and the business rule count reads "whether the 1 active business rule ... uses".
- **A renewal for another account signs the user out, with the right reason.** When Entra answered a background renewal for a different account in the browser, the extension kept the old token, gave the wrong reason ("sign-in settings changed") and tried again on every card. It now removes the token and the confirmed sign-in, says "Microsoft Entra answered for a different account. Sign in again on the options page.", and asks Entra nothing more until the user selects Sign in.
